# 图标成对精确比对（步骤 7.5 详细版）

## 为什么必须有这一步

整页 / 区块级像素 diff（步骤 5、6）对图标**几乎无效**：一个 8×8px 图标在 1438×1127 的整页 diff 中占比不到万分之一，即使图标完全用错，总 diff 率也只动 0.0x%。实测中曾出现"总 diff 6.95% 看起来还行，但 8 个图标全部用错"的情况。

**结论：图标必须单独提取、单独配对、单独判定，不能由宏观 diff 代劳。**

## 一、设计稿侧：提取图标节点

从 `nodes.json`（通道 B）或 MCP 返回的节点树中提取：

| 来源 | 字段 | 用途 |
|------|------|------|
| 图标容器节点 | `name`（常以 `Icon` / `Icon` 结尾，如 `QrIcon`、`PencilIcon`） | 配对用语义名 |
| 节点 | `type`（`VECTOR` / `FRAME` / `COMPONENT` / `INSTANCE`） | 判断是否为图标 |
| 节点 | `absoluteBoundingBox` | 位置与尺寸 |
| 节点 | `fills[].color` | **图标颜色**（重点，常漏） |
| 节点 | `strokes[].color` + `strokeWeight` | 线性图标的颜色 |
| 导出 | `format=svg` 的 path 数据 | 形状指纹 |
| 父级链 | `children` 路径 | 配对用层级路径 |

**聚合规则（重要）**：一个图标在设计稿里常由**多个 VECTOR 子路径**组成（实测 `QrIcon` 有 7 个子路径、`PlusIcon` 有 4 个）。**必须按图标容器聚合为一个图标条目**，不要按子路径逐个与页面比对，否则会产生大量假阳性。

聚合方式：取最近的、名称以 `Icon` 结尾（或 `type` 为 `COMPONENT`/`INSTANCE`）的祖先作为图标单元，其下所有 VECTOR 的 `fills` 取并集作为图标颜色集合，`absoluteBoundingBox` 取外包围盒。

## 二、页面侧：脚本 C 提取图标

脚本：`scripts/extract_icons.js`（在 `browser_evaluate` 中执行）

对每个候选图标元素采集：

| 字段 | 取值方式 | 说明 |
|------|----------|------|
| 选择器 | `tagName + #id + .class` | 定位 |
| 类型 | `svg` / `i`(图标字体) / `img` / 背景图 | 决定指纹算法 |
| 形状指纹 | 见下方"指纹归一化" | 比对核心 |
| 渲染颜色 | `getComputedStyle(el).color` 或 `fill` | **必须取 computed 值** |
| 尺寸 | `getBoundingClientRect()` | 宽高 |
| 位置 | `absoluteBoundingBox` 等价的页面坐标 | 配对用 |
| 邻近文本 | 父元素或兄弟元素的**真实文本** | 配对关键依据 |

**候选元素选择器**：`svg, i, [class*="icon"], [class*="Icon"], img[src*="icon"], [style*="background-image"]`，并排除 `display:none` / 尺寸为 0 的。

## 三、指纹归一化

不同来源的形状数据无法直接比字符串，统一归一化为可比指纹：

1. **SVG path**：取 `path` 的 `d` 属性 → 去除空白与换行 → 坐标保留 **1 位小数**（消除 0.001 级渲染误差）→ 多个 path 按字典序排序后拼接 → 取 MD5 前 12 位。
2. **图标字体**：取 `getComputedStyle(el, '::before').content` 的码点（如 `\e60a`），或元素文本中的私有区字符 → 归一为 `font:<codepoint>`。
3. **位图 / 背景图**：取 URL 文件名 + 图片主色（用 Pillow 取非透明像素均值）→ 归一为 `img:<name>:<rgb>`。

**降级**：若设计稿侧拿不到 svg（如只有 PNG 切图），改用**渲染后裁剪比对**——把设计稿图标区域与页面图标区域各自裁剪成同尺寸 PNG，缩放到 32×32 后算像素差异率：<8% 视为一致，8~25% 记观察项，>25% 判形状不一致。

## 四、配对规则（三要素，按优先级）

1. **邻近文本**（权重最高）：图标附近（父级 / 前一个兄弟 / 后一个兄弟）的**真实文本**相同。例：设计稿 `Btn / SendIcon` 邻近文本为"消息发送" → 匹配页面"消息发送"按钮内的图标。
   - ⚠️ 计算邻近文本时**必须剔除图标字体字符**（Unicode 私有区 `\uE000-\uF8FF` 及零宽字符），否则"图标 i + 文字"结构会把图标误当文本。复用脚本 B 的 `ICON_CHARS` 正则。
2. **层级路径**：设计稿路径末段（如 `Card / CardBody / Btn / SendIcon`）与页面 DOM 路径结构相似。
3. **位置就近**：前两者都无法确定时，按页面坐标与设计稿坐标（都归一化到各自根容器的百分比）就近匹配，距离阈值 5%。

**未配对处理**：设计稿有而页面找不到对应图标 → 记**缺失**；页面有而设计稿无 → 记**新增**，两者都进报告但等级降一级。

## 五、判定矩阵

| 情况 | 等级 | 缺陷类型 | 典型表现 |
|------|------|----------|----------|
| 形状指纹不同 | **高** | 图标不一致 | 图标用错 / 需按设计稿替换 |
| 设计稿有图标，页面无 | **高** | 图标缺失 | 功能入口少了图形标识 |
| 颜色不同（非抗锯齿） | **中** | 图标颜色不一致 | 二维码该是蓝色却是灰/黑 |
| 尺寸差 >2px | **中** | 图标尺寸偏差 | 图标偏大/偏小 |
| 位置偏移 >4px | 低 | 图标位置偏差 | — |
| 仅抗锯齿 / 亚像素差异 | 忽略 | — | 不进报告 |

## 六、按钮中的图标全面对比（如「消息发送」图标 / SendIcon）

⚠️ **图标在按钮内时，只比图标本身会漏检**：用户反馈"消息发送图标与设计稿不一致"，但该图标位于 `<button>` 内——旧流程只抓图标、未抓按钮，按钮背景色 / 文字 / 圆角对不对完全没比对。凡图标命中 `<button>` / `[role=button]` / 含 `btn` 类容器，必须把**整个按钮**作为对比单元。

**设计稿侧（按钮 frame）**，在提取图标节点的同时一并取：

| 字段 | Figma 字段 | 用途 |
|------|-----------|------|
| 按钮文字 | 按钮 frame 内文本节点的 `characters` | 配对 + 文字核对 |
| 按钮背景色 | 按钮 frame `fills[].color` | 背景色对比 |
| 按钮边框 | 按钮 frame `strokes[].color` + `strokeWeight` | 边框对比 |
| 按钮圆角 | 按钮 frame `cornerRadius` / 四角独立值 | 圆角对比 |
| 按钮文字色 / 字号 | 文本节点 `fills[].color` + `style.fontSize` | 文字样式对比 |

**页面侧**：脚本 C（`extract_icons.js`）为每个按钮内图标产出 `container` 字段：

```
container: {
  sel:   "button.send-btn",          // 按钮稳定选择器（document.querySelector 可命中）
  text:  "消息发送",                  // 按钮文字（已剔除图标字符合集）
  bg:    "rgb(0,149,255)",            // 按钮背景色
  color: "rgb(255,255,255)",          // 按钮文字颜色
  radius:"4px",                       // 按钮圆角
  border:"none",                     // 按钮边框
  x, y, w, h                          // 按钮页面坐标包围盒（含 scrollX/scrollY）
}
```

**全面对比维度清单**（逐项核对，任一项不符即记缺陷）：

1. 图标层：形状指纹 / 颜色 / 尺寸（同第五节判定矩阵）。
2. 按钮文字：`characters` ↔ `container.text`。
3. 按钮背景色：`fills[].color` ↔ `container.bg`。
4. 按钮边框 / 圆角：`strokes` + `cornerRadius` ↔ `container.border` + `container.radius`。
5. 按钮文字颜色 / 字号：文本节点样式 ↔ `container.color` / 计算 `fontSize`。

**判定等级**：图标色或按钮背景色不符 = **中**；图标形状不符 = **高**；按钮文字或圆角不符 = **中**；边框不符 = **低**。缺陷 `element` 定位优先记**按钮 `container.sel`**（确保后续能直接定位到问题按钮），`anchor` 注明"图标位于该按钮内"。

## 七、踩坑记录（Gotchas）

1. **图标字体不是文本**：私有区字符 `\uE000-\uF8FF` 会被当成文案，导致邻近文本提取错误、配对失败。务必先用 `ICON_CHARS` 清洗。
2. **颜色要取 computed 值**：CSS 里写 `currentColor` 时直接读 `fill` 属性拿到的是字符串 `currentColor`，必须用 `getComputedStyle` 解析成 `rgb(...)` 才能比对。
3. **按容器聚合，不按子路径**：见第一节"聚合规则"，否则子路径数量差异会造成满屏假阳性。
4. **别信总 diff 率**：总 diff 低不代表图标没问题，这条是本节存在的原因。
5. **线性图标看 stroke 不看 fill**：`fill:none` + `stroke` 的线性图标，颜色取 `strokes[].color`，取 `fills` 会得到空值而误判。
6. **HTTPS 页面无法 fetch http 脚本（mixed-content）**：被比对页面是 `https://` 时，浏览器会拦截从 `http://127.0.0.1` 拉取脚本（"Failed to fetch"）。不要依赖"静态服务器 + fetch + eval"通道（该通道仅对 http 同源页面有效）。**正确做法**：脚本必须写成"反斜杠无关"（所有正则字符类用 `String.fromCharCode` 构造，不出现 `\s` / `\uXXXX` / `\(` 等字面反斜杠），然后**整体内联进 `browser_evaluate` 的 `function` 参数**直接执行。`browser_evaluate` 会把 `function` 包成 `return ( … )`，因此脚本结尾用 `})()`（裸 IIFE 表达式）而**不要写 `})();`**（尾分号会落在 `return (…)` 内导致 `Unexpected token ';'`）。
7. **正则里匹配一个字面反斜杠需写 `\\`（两个反斜杠字符）**：识别图标字体码点转义 `\e60a` 时，若只用 `CH(92)+'([0-9a-fA-F]{4})'` 只生成一个反斜杠字符，正则会把它当成"转义左括号"，继而 `)` 无匹配左括号报 `Unmatched ')'`。必须 `CH(92)+CH(92)+'([0-9a-fA-F]{4})'`。
8. **SVG 与图标字体是异构表示，形状指纹不可直接比**（已知限制）：设计稿多为 SVG（`svg:<hash>`），页面常为图标字体（`font:<codepoint>`）。指纹类型不同 → **形状不能自动判一致/不一致**，只能判"需视觉核对"。能自动判定的是**颜色、尺寸、位置**；若设计稿该图标有 `fills` 颜色而页面颜色不符（如 QrIcon 设计蓝、页面灰），直接记**颜色不一致(缺陷)**。脚本在配对后据此给出"已配对；形状异构需视觉核对 / 颜色一致或缺陷"的判定。**判定为"需视觉核对"的图标必须记入 `report.json` 的 `pendingChecks`（Excel「待确认问题」sheet / HTML 第九章），每条带 `element` 定位（确认位置 + 页面元素），详见 SKILL.md 步骤 7.12 与 report-templates.md 9.3。**
9. **1px `<i>` 分隔线会被图标选择器误抓**：页面里用作横向分隔线的 `<i>` 元素（宽上千、高 1px）会被 `i` 选择器当成图标。提取后按 `h<=2` 或 `w>=200` 过滤出图标结果，但这类元素本身就是分隔线证据，交给步骤 7.7 处理。
10. **邻近文本可能因占位文案而与设计标签不同**：如二维码图标的页面邻近文本是占位 "150*150" 而非设计标签"成员主页地址"。配对需加**选择器/区域特征兜底**（如 `qricon` 类名、`[class*="qricon"]`），不能只靠 near-text 关键字相等。
