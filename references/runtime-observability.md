# 运行期观测（7.35–7.38）

## 为什么需要

静态探测（`extra_checks.js`）只读 DOM 与 computed style；像素/样式比对只看得见"画出来的样子"。两者都**看不到交互过程中发生了什么**：

- 点一下就 `console.error` 或抛未捕获异常（用户看到白屏/卡住）；
- 交互触发的接口 500 / 超时（界面静默、无提示）；
- 按钮没防抖，一次点击发了两次写请求（重复下单/重复提交）；
- 元素被别的层盖住，用户点不到（视觉上"在"，实际不可交互）。

这几类都是**用户真实遇到、静态快照抓不到**的缺陷。本文件把它们变成可机械采集的证据，对应维度 7.35–7.38。

## 怎么用（两阶段，同一文件自动识别）

`scripts/runtime_observability.js` 是页面内脚本（与 `extra_checks.js` 同一套注入方式：`browser_evaluate` 内联执行，全文无反斜杠）。它**调用两次**：

```text
① 页面加载并稳定后（步骤 3 / 5 之间）调用一次
   → 安装钩子，返回 { "mode": "install" }
② 完成本轮交互（点击/提交/打开弹层/路由往返）后调用一次
   → 采集并返回 { "mode": "collect", "findings": [...] }
```

钩子挂在 `window.__vpObs` 上，跨两次 evaluate 保持。**必须在交互之前安装**——先交互再装，前面发生的异常与失败就丢了。

采集结果 `findings` 可直接喂 `normalize_evidence.py`（它按 `findings` 键识别）。

## 维度与判据

| 维度 | 采集方式 | 判据 | 等级 |
|---|---|---|---|
| 7.35 运行期 JS 异常 | hook `console.error` / `window.onerror` / `unhandledrejection` | 任一未捕获错误 → 缺陷（按文本去重） | P1 |
| 7.36 交互期网络失败 | hook `fetch` / `XMLHttpRequest` | 非 2xx；`status>=500` 或网络错误（status 0）→ 缺陷 | 5xx/网络 P1、4xx P2 |
| 7.37 重复请求/重复提交 | 分析写请求时间序列 + 响应结果 | 相同方法+路径+载荷在 **3s 内重复 ≥2 次**；**全部返回成功 → `confirmed`**（客户端重复发了、服务端照单全收，置信 0.85），有失败 → `pending`（服务端拦了，交人工） | P1 |
| 7.38 可交互元素遮挡 | `elementFromPoint` 命中测试 | 中心点命中的最上层元素既非自身也非祖先/后代，且非 `pointer-events:none`；**恒为 `pending` 不自动确认**，按遮挡物是否可交互给置信度（非交互浮层 0.7 / 可交互 0.5）供人工排序 | P1（pending） |

## 保守判据（防假缺陷）

1. **7.37 只统计写方法**（POST/PUT/PATCH/DELETE），避免把轮询 GET 误报成重复提交；且**只在 3 秒窗口内**算重复——间隔久的重试是正常行为。
2. **7.38 命中遮挡时若页面有可见弹层**（`[role=dialog]` / modal / mask）则整体跳过——弹层盖住背景是设计内的，无法区分，不猜。
3. **7.37 保守自动确认、7.38 恒 pending**（v4.13.0）：7.37 仅当**每一个重复写请求都返回成功**才 `confirmed`——这是硬证据（客户端重复发了且服务端未拦）；只要有失败，说明服务端拦掉了重复（有防护），留 `pending` 交人工。（注：若服务端有幂等去重，确认项的严重度或可降，但“客户端重复发送”本身已成立。）7.38 遮挡高度依赖上下文（sticky 头部、有意的浮层），**一律 pending 不自动确认**，只按遮挡物是否可交互给置信度供人工排序。**7.35/7.36 仍是可直接确认的**（异常与 5xx 没有歧义）。

## 安全与边界

- 本脚本**只读取与观测**：安装的钩子记录已有行为，不主动点击、不提交、不发起请求；7.38 只做命中测试，无副作用。
- **未安装钩子就采集 / 本轮未做交互** → 对应维度填 `notRun` 并写明原因，不得凭静态数据填 `pass`。
- 采集有上限（异常 20 条、失败请求 20 条、重复 10 条、遮挡 15 条），被截断时以 `summary` 里的计数为准，报告需说明"仅列前 N 条"。
- 与 7.33（接口异常与慢网络下的界面）的分工：7.33 是**主动拦截**接口造 500 看界面；7.36 是**被动采集**真实交互中发生的失败。两者互补，不互相替代。

## 与其它维度的交叉

- 7.35 的异常位置常与 7.17（表单校验）、7.18（浮层交互）、7.32（路由往返）相关：异常往往在交互后立刻出现，定位到 `source` 后回看对应维度。
- 7.36 的失败请求要结合 7.33 判断是"接口本身问题"还是"前端错误处理缺失"。
- 7.37 与 7.22（按钮点击生效）交叉：按钮生效判定只看到"有变化"，重复提交是"变化发生了两次"。

## 自检

`scripts/tests/runtime_observability_smoke.cjs` 用最小桩全局在 Node 里真跑两遍（安装 → 触发错误 → 采集），
验证脚本可运行且能采到 7.35 异常。改动本脚本后用它自检：`node scripts/tests/runtime_observability_smoke.cjs`。
