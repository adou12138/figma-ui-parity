# 错误处理与降级（步骤 2 附）

本文件由 SKILL.md 步骤 2 下沉而来：错误处理矩阵、重试规则、数据缺失降级、token 中途失效恢复。

#### 错误处理矩阵

| 错误类型 | 可能原因 | 处理方式 |
|----------|----------|----------|
| **401 / 403 / 未授权** | token 失效 | 停止流程，返回步骤 1.2 的 token 更新流程 |
| **404 / 文件不存在（Figma）** | URL 中 fileKey 错误，或文件未共享给该账号 | 提示用户核对 URL，使用 `AskUserQuestion` 请求重新提供 |
| **404 / 资源不存在（测试页面 URL 转抄错）** | 长对话被压缩成摘要时，测试页面 URL 可能被转抄错（例：把 `addressbooksetting.aspx` 写成 `addressbooksettingsettings.aspx`），访问即 404 | 以**用户原始消息**中的 URL 为准，不要沿用摘要里的写法；实测 404 即证伪，立即用原始 URL 重试。详见 `references/headed-login-fallback.md`「URL 转写陷阱」 |
| **429 / 限流** | Figma API 调用过于频繁 | 等待 5 秒后重试一次；连续失败则提示稍后再试 |
| **5xx / 服务器错误** | Figma 服务端异常 | 等待 10 秒后重试一次；连续失败则提示"Figma 服务异常，请稍后重试" |
| **超时** | 网络问题或请求过大 | 重试一次（超时延长至 60s）；连续失败则跳过该步骤并在报告中标注"数据缺失" |
| **返回空数据** | 该节点无对应资源（如无文本样式） | 记录为"该资源为空"，继续下一步，不阻塞流程 |
| **JSON 解析失败** | 返回格式异常 | 尝试用字符串方式解析；若仍失败则记录原始返回内容并跳过 |

**重试规则**：
- 每个工具最多重试 2 次（含首次调用共 3 次机会）
- 重试间隔：第 1 次重试等 5 秒，第 2 次重试等 15 秒
- 连续 3 次失败则标记该数据为"获取失败"，在报告中明确标注，并继续后续步骤

**数据缺失降级策略**：

| 缺失的数据 | 降级处理 |
|------------|----------|
| 节点样式（图层/字体） | 改用 `get_images` 导出的 PNG 截图做像素级对比（步骤 5） |
| 切图资源 | 在报告中标注"图标切图无法获取，建议手动对比图标" |
| 字体信息 | 从设计稿 PNG 截图目测，报告中注明"字体取自截图，非结构化数据" |
| 全部数据获取失败 | 提示用户"无法获取 Figma 数据，请检查 URL、网络和 token 后重试"，终止流程 |

#### token 中途失效的恢复

如果在步骤 2 执行过程中（非预检阶段）出现 401/403 错误：

1. 立即停止当前工具调用。
2. 告知用户"token 在获取数据过程中失效"。
3. 使用 `AskUserQuestion` 询问是否提供新 token 继续。
4. 如用户提供新 token：更新 `mcp.json` 的 `X-Figma-Token` → 从失败的工具调用处重试（无需重新执行已成功的步骤）。
5. 如用户拒绝：保存已获取的数据，生成部分报告并标注"因 token 失效，部分数据缺失"。
